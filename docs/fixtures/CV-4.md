# CV-4 Python-parity fixtures

## Status (2026-10-25)

Committed synthetic fixtures are generated by
[`tools/cv4_fixtures.py`](../../tools/cv4_fixtures.py) with NumPy 2.2.6,
OpenCV 4.11.0 and scikit-learn 1.7.2 from the prototype virtualenv. They
contain no personal data.

`cargo test -p yet-core --test cv4_parity` checks:

- canonical quadrant means for 7×5, 5×7, 8×6 and 103×77 patterns against NumPy;
- sklearn `LinearRegression` predictions on three held-out rows within 0.5 px,
  and coefficients/intercept within 1e-6;
- every pixel of an odd 7×5 RGB image against OpenCV `BGR2GRAY` exactly.

Remaining before the live session path: append a few **real** eye-ROI frames from
the target camera and rerun the same test. The synthetic fixtures pin the
algorithm; real frames add camera format, noise and illumination behavior.

## 1. Committed synthetic fixtures

```text
features/
  pattern_7x5.gray       # raw 8-bit, row-major, no header
  pattern_5x7.gray
  pattern_8x6.gray
  pattern_103x77.gray
  features.csv           # file,width,height,nw,ne,sw,se
regression/
  calibration.csv        # 9 training rows + 3 held-out rows
  predictions.csv        # sklearn predictions for the 3 held-out rows
  coefficients.csv       # sklearn intercept and coefficients
luma/
  colors_7x5.rgb         # raw RGB, 3 bytes per pixel
  colors_7x5.gray        # OpenCV BGR2GRAY
  meta.csv
```

The regression features and targets are quantized to `f32` **before** sklearn
fits, because the Rust model consumes `f32` features. Both sides therefore see
identical numbers; only the solver differs.

## 2. Adding recorded eye-ROI frames

Preferred format is raw 8-bit grayscale (`.gray`), because no image decoder is
needed in the parity test. `yet-zero camera` can write exactly this file:

```sh
cargo run --release -p yet-zero -- camera examples/demo --save-roi /tmp/eye.gray
```

The command prints the negotiated frame size, the ROI rectangle and the
canonical quadrant means for the last valid frame; the saved file contains that
frame's ROI bytes. Append one line per dump to `features/features.csv`.

For frames from another tool:

1. Crop the **eye ROI only**, with no rescaling after the crop.
2. Write the raw bytes and append a row to `features/features.csv`:

   ```csv
   file,width,height,nw,ne,sw,se
   recorded_0001.gray,103,77,154.23,151.07,148.91,150.44
   ```

3. Compute the last four values with the canonical mapping. The Python code
   labels its second and third values `NE` and `SW` but computes bottom-left and
   top-right:

   ```python
   mid_x, mid_y = w // 2, h // 2
   nw = eye[0:mid_y, 0:mid_x].mean()
   ne = eye[0:mid_y, mid_x:w].mean()
   sw = eye[mid_y:h, 0:mid_x].mean()
   se = eye[mid_y:h, mid_x:w].mean()
   ```

4. Include at least one odd width and one odd height across the recorded set.
   The synthetic fixtures already satisfy this, but odd real frames are the
   interesting case.

No Rust test change is needed: the parity test iterates every row in
`features.csv`.

## 3. Regression fixtures

`calibration.csv`:

```csv
nw,ne,sw,se,target_x,target_y
200,128,128,128,572.29998779296875,105.80000305175781
...
```

- Nine training rows are required; the fixture has nine plus three held-out.
- Targets are **monitor pixels**, not normalized coordinates.
- `predictions.csv` holds sklearn predictions for the held-out rows.
- `coefficients.csv` holds `intercept` and the four slopes per output; it is a
  diagnostic, while the 0.5 px prediction check is the acceptance criterion.

To extend with a real calibration run, replace or append the rows, then
regenerate `predictions.csv` and `coefficients.csv` with:

```python
from sklearn.linear_model import LinearRegression
model = LinearRegression().fit(features_train, targets_train)
```

## 4. Luma parity and the ±1 bound

On the committed odd 7×5 fixture, `rec601_luma` matches OpenCV exactly. For
arbitrary colors, OpenCV's 8-bit `BGR2GRAY` uses 15-bit fixed-point
coefficients and can differ from the documented rounding formula by one level.
Example: RGB `(0, 0, 250)` gives 28 in OpenCV and 29 from
`(299R + 587G + 114B + 500) / 1000`. Camera parity must therefore allow a
one-level luma difference, not bit equality.

## Privacy

Eye crops are personal data. Keep recorded `.gray` frames and their per-frame
CSVs out of git; add the directory to `.gitignore` or store the files outside
the repository. The committed synthetic fixtures and the aggregate
calibration/prediction CSVs are safe to share.
